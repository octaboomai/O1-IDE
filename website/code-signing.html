Code signing policy

Last updated: October 2026

This page describes how o1 IDE release artifacts are built and code signed. It is published in accordance with the requirements of the SignPath Foundation open-source code signing programme.

Free code signing provided by SignPath.io, certificate by SignPath Foundation.

What we sign

  • The Windows installer published on our GitHub Releases page — o1-ide-<version>-windows-x64.exe.
  • No other artifacts are signed at this time. Linux artifacts (.deb, .AppImage) are distributed unsigned; verify them against the checksums on the Releases page.

Build and signing process

  • All release artifacts are built from the source in our public repository by GitHub Actions CI (.github/workflows/release.yml). No release artifact is built or signed on a developer machine.
  • Only CI-built artifacts from the tagged commit are submitted for signing.
  • The code signing private key is generated and held by SignPath.io in a Hardware Security Module (HSM). o1 IDE never holds or has access to the private key.
  • Every signing request is manually approved by a project approver, and each signed file is timestamped.

How to verify a signed build

On Windows, check the Authenticode signature before installing:

Get-AuthenticodeSignature .\o1-ide-0.1.0-windows-x64.exe | Format-List

Or, with the Windows SDK: signtool verify /pa /v o1-ide-0.1.0-windows-x64.exe. A valid signature shows the publisher as SignPath Foundation.

Privacy

o1 IDE does not transfer any information to other networked systems unless specifically requested by the user or the person installing or operating it. See our Privacy Policy for details.
